# DocTology Wiki Studio

업데이트: 2026-09-06. 실제 위키 경로와 Pi 인증은 실행 환경에서 확인하세요.

대화를 중심으로 내 위키를 읽는 로컬 작업실입니다. 왼쪽에는 워크스페이스와 대화 기록, 가운데에는 채팅, 오른쪽에는 전체 지식 그래프와 선택한 답변의 참고문헌을 표시합니다. 원문 합성과 검증은 별도의 **위키 작업** 화면에서 실행합니다.

## 실행과 연결

Python 3.11 이상으로 실행합니다. 웹 패키지 설치나 빌드는 필요 없습니다.

### 더블클릭으로 실행

1. 저장소 맨 위에서 macOS는 [Wiki-Studio.command](../Wiki-Studio.command), Windows는 [Wiki-Studio.bat](../Wiki-Studio.bat)를 더블클릭합니다. 이 두 파일은 DocTology 런타임의 실행기로 전달만 합니다. 저장소 전체를 함께 두세요.
2. Python 버전을 확인한 뒤 로컬 서버를 켜고 기본 브라우저를 엽니다. 처음에는 예시 화면이며, **왼쪽 위 워크스페이스 → 폴더 선택 → 위키 연결하기**로 기존 위키를 연결합니다. 새 위키를 자동 생성하지 않습니다.
3. 실행 중에는 터미널 창을 유지합니다. 종료할 때 **Ctrl+C**를 누르세요. 진행 중인 작업은 먼저 화면에서 중단하는 편이 좋습니다. 이미 반영된 파일을 되돌리는 기능은 아닙니다.

실행 본체는 DocTology의 [runtime/wiki_dashboard.py](../runtime/wiki_dashboard.py)이고 UI는 루트의 이 `dashboard/` 폴더입니다. 루트 실행 파일은 [runtime/start_dashboard.command](../runtime/start_dashboard.command)와 [runtime/start_dashboard.bat](../runtime/start_dashboard.bat)로 전달합니다. 스킬만 설치해서는 웹 앱이 설치되지 않습니다. DocTology 저장소 전체가 필요하며, 기존 스킬 내부의 앱 경로는 더 이상 사용하지 않습니다.

- **Python이 없거나 너무 오래되면:** 안내를 표시하고 멈춥니다. Python 3.11 이상을 설치하세요. Windows에서는 PATH 등록도 확인합니다. 자동 다운로드·패키지 설치는 하지 않습니다.
- **Pi가 없으면:** 문서·그래프 탐색은 가능하지만 AI 채팅·원문 작성은 Pi 설치와 인증 후 사용할 수 있습니다. 기본 실행은 위키 미연결이므로 감시나 모델 작업도 시작하지 않습니다. `--repo-root`로 지정한 위키의 기존 opt-in 설정은 기존 서버 동작을 따릅니다.
- **브라우저가 안 열리면:** 터미널에 출력된 주소를 직접 엽니다. 서버는 계속 실행됩니다. OS 보안 정책이나 기본 브라우저 설정을 바꾸지 않습니다.
- **4317 포트를 사용 중이면:** 기존 서비스를 건드리지 않고 최대 100개 포트 범위에서 빈 포트를 선택합니다. 실제 주소는 터미널에 표시됩니다. 포트가 바뀌면 브라우저 대화 기록도 별도 공간이 됩니다. 기존 기록은 삭제하지 않지만 자동 이동하지는 않습니다. 이미 실행한 창이 있다면 그 주소를 계속 사용하세요.
- **특정 Python을 사용하려면:** `WIKI_STUDIO_PYTHON` 환경변수에 실행 파일의 전체 경로를 지정합니다. macOS 실행기는 Homebrew와 흔한 사용자 도구 경로도 확인합니다.
- **macOS에서 실행 권한이 사라졌으면:** 저장소에서 `chmod +x Wiki-Studio.command`를 실행하거나 `bash Wiki-Studio.command`로 실행합니다. 다운로드 파일의 OS 보안 차단은 자동으로 해제하지 않습니다.

두 실행 파일 모두 인자를 전달합니다. 예: `./Wiki-Studio.command --port 4400 --repo-root "/path/to/wiki"` 또는 Windows의 `Wiki-Studio.bat --port 4400 --repo-root "C:\path\to\wiki"`. 브라우저 열기와 포트 자동 선택을 끄려면 `--no-open-browser --no-auto-port`를 추가합니다.

### 터미널에서 직접 실행


```bash
python3 runtime/wiki_dashboard.py --repo-root /absolute/path/to/wiki
```

기본 주소는 `http://127.0.0.1:4317`입니다. 다른 서비스가 사용 중이면 `--port 4318`처럼 다른 포트를 선택하세요. 모델 호출 없이 예시 화면을 보려면 위키 경로 없이 실행합니다. 스킬 전역 설치와 이 애플리케이션 실행은 별개입니다.

왼쪽 위 워크스페이스 버튼에서 **폴더 선택…**을 누릅니다. macOS와 Windows에서는 표준 폴더 선택 창을 사용하며, 창 서비스가 없는 제한된 실행 환경에서는 작업실의 클릭형 폴더 선택기로 전환합니다. **작업실에서 폴더 찾기**로 바로 탐색할 수도 있습니다. 상위 폴더와 하위 폴더를 클릭한 뒤 **이 폴더 선택**을 누르면 경로가 채워집니다. 마지막 **위키 연결하기**는 기존 구조 검사와 실행 중 전환 제한을 그대로 거칩니다. 경로 직접 입력도 보조 옵션으로 남습니다.

폴더 선택은 파일 업로드나 연결 변경이 아닙니다. 내장 선택기는 현재 방문한 폴더의 하위 폴더 이름만 한정해 읽고, 파일 내용이나 폴더 전체를 수집하지 않습니다. 숨김 폴더·심볼릭 링크 항목은 제외하며 표시 한도를 넘으면 알립니다. 취소하거나 연결 창을 닫으면 선택을 적용하지 않습니다. 네이티브 선택기는 로그인한 데스크톱 세션이 필요하며, 운영체제 권한·보안 정책을 변경하지 않습니다.

- **작업용 위키:** loop 사전 검사를 통과한 `AGENTS.md`, `raw/`, `wiki/` 구조입니다. 읽기 전용 채팅, 문서 탐색, 원문 업로드와 합성을 지원합니다.
- **프로젝트 문서:** `AGENTS.md`와 `wiki/`는 있지만 원문 합성 요건이 없는 DocTology 같은 저장소입니다. 채팅과 실제 문서 탐색만 허용하며 서버에서도 업로드·합성을 차단합니다.

연결 후 왼쪽 위에 **로컬 위키** 또는 **프로젝트 문서 · 읽기 전용**이 표시됩니다. 원문 작업이 필요하지만 읽기 모드로 열리면 `wiki_loop.py --repo-root /absolute/path/to/wiki preflight`로 부족한 요건을 확인하세요.

연결은 새 위키를 만드는 동작이 아닙니다. 새 위키의 폴더 구조는 [llm-wiki-bootstrap](../.agents/skills/llm-wiki-bootstrap/SKILL.md)으로 먼저 생성합니다. 사전 검사와 기존 합성·인증 게이트의 자세한 계약은 [loop 스킬](../.agents/skills/llm-wiki-loop/SKILL.md)을 따릅니다. 이 안내는 Pi가 설치·인증된 환경을 전제로 하며 실제 운영 검증 환경은 macOS입니다.

## 대화에서 근거까지

1. 가운데 입력창에서 질문하거나 실제 문서 제목으로 만든 추천 질문을 선택합니다.
2. Pi가 `wiki_list`, `wiki_search`, `wiki_read`, `wiki_links`를 반복 호출해 필요한 문서를 찾고 읽습니다. “위키내용 요약해줘” 같은 질문은 목록·색인부터 시작하고, 여러 문서가 필요한 질문은 발견한 링크와 단서를 따라갑니다. 고정된 한 번의 검색이나 고정 홉 수에 묶이지 않습니다.
3. 생성 중에는 실제 도구 호출·읽은 문서 수, 펼쳐 보는 탐색 기록, 부분 답변과 경과 시간을 보여줍니다. **응답 중단**으로 취소할 수 있으며, 생성 중 새 대화나 기록 전환은 막습니다.
4. 답변의 번호 인용과 오른쪽 참고문헌을 누르면 문서 본문이 열립니다. 제목과 X 닫기 버튼은 고정되고 본문만 스크롤되므로 끝까지 읽어도 바로 닫을 수 있습니다. 다른 문서를 열면 본문은 맨 위부터 시작합니다. 이전 답변을 선택하면 그 답변의 참고문헌으로 바뀝니다.
5. 전체 그래프에서 인용 문서를 강조합니다. 강조 경로는 실제 문서 링크를 연결한 탐색 경로이지, 모델의 사고 과정이나 인과 관계가 아닙니다.
6. 문서에 확인 가능한 raw 링크 또는 현재 원문과 연결된 적용 기록이 있으면 **연결된 원문**이 나타납니다. 원문이 없으면 링크를 꾸며내지 않습니다. 본문의 확인 가능한 위키·상대 Markdown 링크도 이동할 수 있습니다.

**위키 작업과 대화는 동시에 실행할 수 있습니다.** 위키 정리 중에도 새 대화를 열고 질문할 수 있으며, 한쪽의 중단 버튼은 다른 쪽을 멈추지 않습니다. 답변은 읽은 시점의 문서를 기준으로 합니다. 위키 전체가 완성된 상태를 고정해서 읽는 방식은 아니므로 정리 중에는 이를 화면에 안내합니다. 이 대시보드에서 작업이나 응답이 실행 중이면 연결 폴더 변경은 계속 막습니다.

목록·검색·링크 발견과 실제 본문 읽기는 구분합니다. `wiki_read`로 읽은 문서만 번호 근거가 되고, 그중 답변이 명시적으로 인용한 문서만 참고문헌에 표시합니다. 번호 인용은 출처 표시이지 주장과 인용문의 의미적 일치나 위키 인증을 자동 검증했다는 뜻이 아닙니다. 실패 시 가짜 답변을 만들지 않습니다. 답변 종료 전에 바뀌거나 사라진 문서는 유효 인용에서 제외합니다. 이후 인용을 열 때도 현재 문서의 해시가 당시 읽은 값과 다르면 변경을 알립니다.

한 질문의 탐색 한도는 도구 64회, 서로 다른 본문 24개, 반환 본문 합계 160,000자입니다. 본문은 한 번에 최대 10,000자씩 이어 읽으며 파일당 2MB를 허용합니다. 목록은 40개씩 넘길 수 있습니다. 도구 결과의 잘림과 남은 한도를 확인하도록 모델에 지시하고, 예산이 소진되면 화면에도 경고합니다. 일부만 읽은 답변을 전체 위키를 빠짐없이 검토한 결과로 간주하지 마세요. 한도에 도달하면 질문을 주제별로 나누거나 다음 질문에서 아직 읽지 못한 문서를 지정하세요.

긴 대화에서는 입력창 바로 위의 **맨 위 / 맨 아래** 버튼으로 이동합니다. 이미 도착한 방향은 비활성화되며 짧은 대화에는 버튼이 나타나지 않습니다. 버튼은 본문이나 입력창을 가리지 않고, 모션 줄이기 설정도 따릅니다.

그래프는 최대 80개 문서를 표시합니다. 그 이상이면 인용 문서와 실제 연결 경로를 우선 표시하고 표시 수와 전체 수를 함께 안내합니다. 작은 화면에서는 오른쪽 패널을 버튼으로 펼칩니다.

## 검색 상태와 답변별 사용량

Wiki Studio의 연결된 워크스페이스 폴더 아래 **SQLite / ONNX** 표시를 누르면 검색 상태 상세 창이 열립니다. **상태 다시 확인**은 읽기 전용입니다. 화면이 보일 때 최대 30초 간격으로 갱신하며, 확인 시각도 표시합니다.

- **SQLite:** 설정 유무와 인덱스 없음·최신(stat)·오래됨·확인 불가를 구분합니다. 최신(stat)은 인덱스 메타데이터와 파일 경로·크기·수정 시각의 일치이며, 본문 전체의 정확한 검증이나 검색 품질 보증이 아닙니다. 지원하지 않는 스키마, 변경 중인 DB, WAL/저널, 검사 한도 초과는 정상으로 추정하지 않습니다.
- **ONNX:** 현재 서버 Python의 `onnxruntime`·`tokenizers`·`numpy` 패키지 존재와 `WIKI_ONNX_MODEL`·`WIKI_TOKENIZER` 환경변수가 가리키는 파일 존재를 확인합니다. 다른 터미널의 환경이나 CLI 옵션은 확인하지 않습니다. **설정됨 · 추론 미검증**은 모델 실행 성공이 아닙니다.
- **벡터:** 저장된 행 수만 보여 줍니다. 벡터 유효성, 모델 호환성 또는 의미 검색 준비 완료를 뜻하지 않습니다.

현재 채팅은 Python 문자열 검색(grep 방식)과 위키링크 탐색을 사용합니다. 외부 grep 명령을 실행하는 것은 아닙니다. SQLite FTS와 벡터가 별도로 준비되어 있어도 **현재 채팅에는 미연결**이며, 상태 표시가 이들을 자동으로 사용하게 만들지 않습니다.

새 답변의 **검색 호출 구성**은 그 답변의 생성 시작부터 종료까지 정상 완료된 호출을 집계합니다. 각 경로의 비율은 `해당 경로 호출 수 ÷ 네 경로 호출 수의 합`이며, 정수로 반올림한 합이 100%가 되도록 표시합니다. 생성 중에는 현재까지의 누적값입니다. 결과가 없는 검색도 호출 1회로 셉니다. 목록 조회·본문 읽기는 별도 집계하고, 실패·한도 거부는 비율에서 제외합니다. 이 비율은 답변 기여도·정확도·인용 비율이 아닙니다. 결과 건수 역시 중복될 수 있으며 고유 문서나 인용 수가 아닙니다.

검색 호출이 없으면 비율을 표시하지 않습니다. 예전 답변은 **검색 사용량 기록 없음**으로 남기며, 잘린 탐색 로그에서 비율을 추정하지 않습니다. 새 집계는 로그 표시 한도와 별도로 유지되고 브라우저의 대화 기록에도 보관됩니다. 상태 조회와 집계는 모델 설치·로드·추론·다운로드·인덱스 재생성이나 자동 실행을 시작하지 않습니다.

## 모델과 대화 기록

채팅은 설치된 Pi CLI의 RPC 인터페이스를 사용합니다. 모델 입력을 비우면 Pi 기본 설정을 따릅니다. 서버 실행의 `--chat-model`과 `--chat-agent-dir`는 채팅에만 적용되는 명시적 재정의입니다. 원문 합성 프로세스는 기존 Pi 설정을 유지합니다.

정상 연결은 질문 전송 후 실제 답변이 나오고, 답변의 번호 인용을 눌러 해당 문서가 열리는 것으로 확인합니다. 설치 표시만 있고 응답이 실패하면 대시보드를 시작한 터미널에서 `pi --version`이 실행되는지 확인하고, Pi 터미널의 `/login`과 `/model`에서 인증과 모델을 확인하세요. Pi 0.82.1의 RPC·확장 동작을 기준으로 하며, 다른 버전도 `--no-builtin-tools`, 명시적 확장 로딩과 같은 최종 종료 이벤트를 지원해야 합니다.

Pi의 ChatGPT 구독 연결은 Pi의 공식 OpenAI Codex 로그인으로 설정합니다. 대시보드가 계정 비밀번호나 API 키를 입력받지는 않습니다. 실행 파일을 발견했다는 표시와 모델 인증·응답 성공은 다릅니다.

채팅은 기본 파일·셸 도구, 확장·스킬 자동 탐색과 컨텍스트 파일 로딩을 끈 별도 Pi 프로세스입니다. DocTology 런타임이 소유한 읽기 전용 확장 하나만 명시적으로 로드하고, 작업별 토큰을 가진 localhost 브리지가 준비된 뒤에 질문을 보냅니다. 확장을 초기화하지 못하면 실패를 알리며 도구 없는 답변으로 대체하지 않습니다. 모델에는 연결된 위키·프로젝트의 승인된 문서만 읽는 네 도구를 제공하고 범용 셸·파일 쓰기·외부 웹 접근 도구는 제공하지 않습니다. 채팅은 대상 파일이나 실행 원장을 쓰지 않습니다. 서버의 채팅 상태는 메모리에 있고 재시작하면 사라집니다. 일시적인 상태 조회 실패는 실행 ID와 중단 버튼을 유지한 채 재연결하며, 실패를 곧바로 모델 종료로 취급하지 않습니다.

대화 기록과 인용 발췌는 이 브라우저의 로컬 저장소에 워크스페이스별로 보관합니다. **지우기**는 현재 워크스페이스의 브라우저 기록만 삭제합니다. 이는 그 자체로 위키 저장·인증이 아니며 다른 기기로 동기화되지 않습니다. 아래의 명시적 **대화를 위키 원문으로 저장** 절차만 예외적으로 원문과 작업 대기열을 만듭니다.

**로컬 화면이라고 모델 호출까지 로컬인 것은 아닙니다.** 질문을 보내면 질문, 제한된 최근 대화와 탐색 중 반환된 문서 목록·검색 발췌·본문·링크가 선택한 Pi 모델에 전달됩니다. 클라우드 모델이면 해당 제공자의 데이터 처리 정책과 계정 사용량이 적용됩니다. 연결·탐색만으로 모델을 호출하지 않습니다.

## 대화를 위키 원문으로 저장

완성된 답변의 메뉴에서 현재 질문·답변 또는 전체 대화를 고른 뒤 서버가 만든 Markdown을 먼저 확인합니다. 미리보기는 대상 파일을 쓰지 않으며 현재 연결 루트에 묶인 불투명 ID로 메모리에 최대 10분 보관됩니다. 한 번에 최대 40개 메시지, 참조 데이터를 포함해 총 100,000자, 메시지당 최대 24개 참조를 허용합니다. 잘렸거나 사용자·어시스턴트 양쪽이 없는 대화, `system` 역할, 클라이언트가 지정한 저장 경로는 거부합니다.

Markdown은 브라우저가 전달한 대화를 실행 지시가 아닌 인용 데이터로 감싸고 `kind: conversation_record`, `source_type: conversation_record`, `provenance_kind: client_supplied_unverified`, `verification_status: unverified`를 기록합니다. 서버가 생성한 답변임을 인증하는 기록은 아닙니다. 현재 승인된 문서 목록에 실제로 존재하는 참조만 상대 링크와 미리보기 시점 해시로 남습니다. 후보 제목·번호·발췌문은 당시 대화 기록일 뿐 검증된 주장으로 승격되지 않습니다. 참조 문서가 승인 뒤 바뀌면 새 미리보기를 요구합니다.

사용자가 미리보기를 승인해야만 표시된 Markdown과 정확히 같은 UTF-8 바이트를 `raw/inbox/conversations/chat-<내용 SHA-256>.md`에 비덮어쓰기 방식으로 보존합니다. 같은 내용은 같은 경로와 대기열 항목으로 수렴합니다. 저장 뒤에는 기존 `llm-wiki-loop`의 `full` 커버리지·검토·인증 게이트를 통과하도록 순차 대기열에 명시적 실행 요청을 넣으며, 대화 자체를 정본 위키나 검증된 외부 사실로 직접 쓰지 않습니다. 대기열 등록이 실패하면 이미 보존한 raw 경로를 알리고 같은 미리보기로 복구할 수 있습니다. 프로젝트 읽기 모드에서는 미리보기와 저장을 모두 거부합니다.

## 폴더 감시와 순차 대기열

**위키 작업 → 폴더 감시**는 현재 연결한 작업용 위키에서만 켜는 선택 기능입니다. 기본값은 감시 꺼짐과 자동 실행 꺼짐입니다. 감시 경로는 연결 루트의 `raw/` 또는 그 하위 폴더, 아니면 대상 위키와 겹치지 않는 독립 외부 폴더입니다. 서버가 실행 중이고 그 루트가 계속 연결된 동안에만 감시합니다.

- 대상은 숨김 항목과 심볼릭 링크를 제외한 Markdown입니다. 파일당 최대 2MB, 한 번의 스캔당 최대 500개이며, 같은 내용이 두 번 연속 관측된 뒤에만 변경을 대기열에 넣습니다.
- 처음 감시를 켤 때 기존 파일은 기준선으로만 기록해 기본적으로 대기열에서 제외합니다. **기존 파일 포함**을 명시한 경우에만 기존 파일도 안정 관측 뒤 후보가 됩니다.
- 내부 `raw/` 파일은 제자리 경로를 사용합니다. 외부 파일은 정확한 바이트의 해시 이름 스냅샷을 `raw/inbox/watched/`에 새로 보존합니다. 원래 외부 파일을 수정하거나 삭제하지 않으며, 외부 삭제를 감지해도 기존 raw나 wiki를 지우지 않습니다.
- **감시 켜기**와 **자동 실행**은 별도 설정입니다. 감시만 켜면 변경을 대기열에 쌓고, 자동 실행까지 켜면 감시가 만든 pending 항목을 하나씩 시작합니다. 감시를 끄면 새 스캔과 그 자동 실행은 멈춥니다. 사용자가 누른 **실행**과 승인한 대화 저장은 명시적 실행 요청이므로 감시가 꺼져 있어도 시작될 수 있습니다.
- 대기열은 원문 경로와 내용 해시로 중복을 합칩니다. 더 새 내용이 실행 전에 오면 이전 pending 항목을 `superseded`로 남깁니다. 중단되거나 게이트 없이 끝난 실행은 `needs_attention`이며 자동 재시도하지 않습니다.
- `completed`는 현재 raw 해시와 기존 source run·batch 게이트가 모두 현재인 경우에만 표시합니다. 이후 원문이나 게이트가 달라지면 `needs_attention`으로 내려갑니다. 현재 게이트가 복구되면 모델을 다시 호출하지 않고 완료 표시를 복구합니다. **재시도**는 사용자의 별도 요청입니다.
- 감시 폴더를 바꿔도 이전 폴더의 대기 항목은 보존하지만 자동으로 시작하지 않습니다. 필요하면 직접 실행하세요. 대기열은 100개씩 **이전/다음**으로 탐색하며 전체 개수를 함께 표시합니다.
- 다른 대시보드가 쓰기 잠금을 사용 중이면 대기합니다. 서버가 중단된 뒤 이전 Pi가 살아 있어도 새 실행·원문 저장·외부 파일 복사를 차단합니다. 외부 편집기나 터미널 전체를 통제하는 샌드박스는 아닙니다.

## 원문 합성과 검증

### 여러 원문의 병렬 준비

사용자가 작업 화면에서 **2~12개** 원문을 명시적으로 선택하면 기존 배치
절차 안에서 초안을 병렬 준비합니다. 기본 동시 작업 수는 **3**, 선택 가능한
상한은 **4**이며, 원문 하나는 기존 단일 원문 흐름을 그대로 사용합니다.
서버가 `parallelPreparationAvailable` 기능을 제공하지 않는 이전 버전이면 이
선택기는 숨겨지고 기존 화면만 보입니다.

각 원문 작업자는 현재 연결 루트와 문서 목록에 묶인 `wiki_list`,
`wiki_search`, `wiki_read`, `wiki_links`와 자기 초안 영역의 `draft_write`,
`draft_submit`만 사용합니다. 원문과 `AGENTS.md`, `wiki/_meta/index.md`를
완전히 읽고 해시가 그대로일 때만 초안을 제출할 수 있습니다. 작업자는
`state/wiki_batches/` 아래의 자기 초안만 기록하며 canonical wiki를 쓰지
않습니다. 준비 상태, 읽기 근거, 원문 해시와 초안 해시는
`state/dashboard_jobs/parallel/`에 남지만, 초안 준비는 반영·검토·인증이
아닙니다. 각 작업자는 자기 원문과 기존 `wiki/`, 정확한 `AGENTS.md`만
읽습니다. 원문과 운영 규칙, 색인의 전체 읽기 및 해시 일치가 제출 조건입니다.
작업자별 한도는 도구 호출 256회, 읽은 문서 64개, 반환 400만 문자이며 한 번의
읽기는 10,000자입니다. 초안은 최대 32개 파일, 파일당 256KiB, 총 4MiB이고
입력 파일은 2MB 이하입니다. 일반 채팅의 더 작은 탐색 한도는 바뀌지 않습니다.

코디네이터는 처음에는 같은 읽기 도구와 `wiki_prepare_batch`만 사용합니다.
선택한 모든 원문이 같은 고정 배치에 유효한 초안을 제출한 뒤에만 원래 내장
도구가 복구되고, 계획용 읽기 도구는 종료됩니다. 이후에도 기존 batch plan, 연결된 각 source run의 세 단계 사전 기록,
state 안의 의미적 충돌 조정, 한 번의 apply, 질문 영수증, snapshot
seal만이 완료 권한을 가집니다. apply 또는 stale 상태의 배치는 다시 준비할 수
없습니다. 기존 `batch status`/복구 경로를 따르거나 새 배치를 만드세요.

초안이 모두 준비됐지만 apply 전에 코디네이터가 끝났다면 **통합 재개**로
같은 배치와 초안을 재사용합니다. 이 동작은 준비 작업자를 다시 실행하거나
검증을 생략하지 않습니다.

원문별 **중단**과 **재시도**는 명시적 동작이며 다른 준비 작업을 취소하지
않습니다. 대시보드 재시작이나 중단된 worker는 자동으로 모델을 재개하지
않고, 현재 해시와 고정 입력을 다시 확인합니다. 재개한 코디네이터에는 저장된
원문별 지시문을 그대로 전달합니다. 이전 프로세스의 종료 확인 전에는 재시도를
허용하지 않습니다. run 생성 직후 기록 연결 전에 강제 종료되어 고아 run 후보가
남은 경우에는 자동으로 새 run을 만들지 않습니다. 후보를 검토하고 기존
`batch link-run`으로 연결하는 수동 복구가 필요합니다. 자동 대기열이 묶을 수 있는
대상도 각각 이미 승인되고 현재 해시인 pending 원문뿐이며, 병렬 재시도는
형제 원문을 기존 단일 원문 쓰기로 쪼개지 않습니다. 폴더 감시와 `autoRun`은
계속 별도 opt-in이며 기본값은 꺼짐입니다. 읽기 전용 대화는 이 쓰기 흐름과
독립적입니다.

**위키 작업 → 자료 추가 → 위키 만들기**에서 별도의 쓰기 작업을 시작합니다. 업로드는 파일당 2MB 이하의 Markdown만 지원하고 기존 파일을 덮어쓰지 않습니다. 실행 중에는 추가 지시와 중단, 원문별 칸반, 절차 기록, 반영량과 실행 기록을 봅니다.

- Pi 실행에는 `agent_settled`를 제공하는 버전이 필요합니다. 기본 어댑터는 Pi 0.82.1을 대상으로 검증했습니다.
- 에이전트 종료는 위키 완료가 아닙니다. 현재 원문 실행과 연결된 배치가 기존 loop 검증·인증을 통과해야 완료로 표시합니다.
- 내용 처리량은 현재 원문 해시와 맞고 수량이 균형을 이루는 단일 적용 full 반영 기록에서만 집계합니다. 반영·사유 있는 제외·보류를 구분하고, 기록이 없거나 오래됐으면 비율을 만들지 않습니다.
- 중단은 이미 반영된 파일을 되돌리지 않습니다. 서버 재시작 후 모델을 자동 재실행하지 않습니다. 새 요청은 기존 작업 기록을 확인하도록 전달합니다.
- 위키 작업·원문 업로드·대화 원문 저장은 같은 쓰기 잠금을 따릅니다. 위키 작업 중 추가 저장은 작업 종료 후 다시 시도해야 하지만, 읽기 전용 대화는 이 잠금을 점유하거나 대기열 실행을 막지 않습니다. 외부 터미널이나 Obsidian 편집까지 잠그지는 않으며 외부 변경은 기존 검증이 감지합니다.

원문 합성 Pi와 감시·대화 저장으로 시작한 작업도 로컬 계정 권한의 도구를 사용합니다. 이 기능은 샌드박스가 아닙니다. 새 의미 검증기를 추가하지 않으며 완료 판정은 기존 loop 게이트에만 위임합니다. Claude Code 실행기와 새로운 DAG 실행기는 이 버전에 포함하지 않습니다.

## 소유권과 검증 범위

루트의 `dashboard/` UI와 `runtime/` 서버·실행 모듈은 DocTology 본체가 소유합니다. `runtime/wiki_loop_adapter.py`가 루프 스킬의 위치와 기존 게이트 구현을 연결하며, 스킬은 대시보드를 import하거나 포함하지 않습니다. 생성한 위키에는 이 실행 파일이나 UI를 복사하지 않습니다. 합성 작업의 연결 메타데이터와 세션은 대상 위키의 `state/dashboard_jobs/`, 감시 설정·기준선·대기열은 `state/dashboard_automation/`에 남지만 기존 source run과 batch 게이트를 대체하는 완료 원장은 아닙니다.

localhost 바인딩, Host·Origin·세션 토큰 검사, 문서 목록과 경로 제한을 사용합니다. 공개 호스팅이나 다중 사용자 서비스는 지원하지 않습니다. 상태 화면은 약 2.5초마다 갱신하고 원문 상태 스냅샷은 최대 4초 캐시합니다. 대규모 위키 성능은 별도 측정이 필요합니다.

```bash
python3 -m unittest discover -s tests -p "test_wiki_dashboard*.py"
node --test tests/dashboard/*.test.cjs
```

Python 테스트는 임시 위키·HTTP 서버·제어 가능한 RPC 프로세스를 사용합니다. JavaScript 테스트는 렌더링·상태 계약을 검사하며 실제 브라우저나 모델 품질 검증을 대신하지 않습니다. 실제 모델 호출과 브라우저 검증의 결과는 각 실행 환경에서 별도로 기록해야 합니다.

## 유지보수와 확장 경계

화면이나 실행 정책을 바꾸지 않는 기능 분리는 아래 소유권을 따릅니다. 별도 프런트엔드 빌드 과정은 없습니다.

| 변경할 내용 | 소유 모듈 |
|---|---|
| 루프 스킬 위치와 기존 게이트 연결 | [wiki_loop_adapter.py](../runtime/wiki_loop_adapter.py) |
| 서버 조립, 워크스페이스 전환, 채팅·쓰기 프로세스 수명 | [wiki_dashboard.py](../runtime/wiki_dashboard.py) |
| 문서 목록, 링크·근거, 문자열 후보, 기존 게이트 기반 스냅샷 | [wiki_dashboard_documents.py](../runtime/wiki_dashboard_documents.py)의 `DocumentCatalog` |
| OS 선택 창과 제한된 폴더 탐색 | [wiki_dashboard_folders.py](../runtime/wiki_dashboard_folders.py) |
| HTTP, 인증 검사, 상태 코드, 정적 파일 제공 | [wiki_dashboard_http.py](../runtime/wiki_dashboard_http.py) |
| SQLite·ONNX 읽기 전용 진단 | [wiki_dashboard_retrieval_status.py](../runtime/wiki_dashboard_retrieval_status.py) |
| 브라우저 상태·저장소, 비동기 요청·취소·오래된 응답 방어, 이벤트 연결 | [app.js](app.js) |
| 대화 직렬화·검증 | [history-codec.js](modules/history-codec.js) |
| 검색 호출 구성과 상태 표시 | [retrieval-usage.js](modules/retrieval-usage.js), [retrieval-status.js](modules/retrieval-status.js) |
| 안전한 Markdown·인용 렌더링 | [markdown.js](modules/markdown.js) |
| 그래프 배치·인용 경로·표시 | [graph.js](modules/graph.js) |

문서 카탈로그는 서버 조립부가 `wiki_loop_adapter.py`를 통해 루프 스킬에서 읽은 `workflow`와 `wiki_batch`를 생성자로 받습니다. 완료 판정을 새로 구현하거나 서버 전체를 다시 import하지 않습니다. 기존 Python 호출자는 `wiki_dashboard.py`의 호환 별칭을 계속 사용할 수 있습니다.

프런트엔드 모듈은 내부 조립용 `WikiStudioModules`에 팩토리만 등록합니다. 이는 외부 플러그인 API가 아닙니다. 입력 데이터·정책 한도·필요한 함수는 명시적으로 전달하고, 앱 전역 변수나 브라우저 저장소를 직접 참조하지 않습니다. 변경 가능한 앱 상태와 요청 세대 번호는 `app.js`에 남습니다.

[index.html](index.html)의 `defer` 스크립트 목록이 로딩 순서와 HTTP 제공 목록의 기준입니다. 모듈을 추가하면 이 목록에 등록하고 마지막 [boot.js](boot.js) 앞에 둡니다. HTTP 제공 목록은 서버 시작 시 읽으므로, 서버를 재시작해야 새 목록이 반영됩니다. 임의 폴더를 웹에 공개하거나 inline script를 추가하지 마세요.

UI 계약 테스트는 HTML에 선언된 실제 파일을 변형 없이 읽습니다. 별도 콜드 부팅 테스트는 `boot.js`까지 실행하며, 모듈 단독 테스트는 앱 전역 없이 주요 계산·렌더링을 호출합니다. 새 기능도 독립 테스트와 실제 HTTP 자산 제공 검사를 함께 통과해야 합니다. 현재 프로세스·잠금·완료 게이트를 다루는 동작은 기존 통합 테스트를 유지하세요.
