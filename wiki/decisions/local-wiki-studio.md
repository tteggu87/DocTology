# Wiki Studio 작업 배경과 다음 작업자 인수인계

## 한눈에 보는 결론

2026-09-05~06에 **자료를 맡겨 위키를 만드는 작업실**을 구현하고, **근거를 따라 대화하는 화면**을 중심에 놓았다. 읽기 전용 채팅과 원문 합성은 독립적으로 실행한다. 승인된 대화 저장과 선택형 감시는 기존 대기열로 들어가며, 여러 원문은 병렬로 준비하되 정본에는 한 작성자만 반영한다. 이후 클릭형 폴더 연결, 실제 검색 사용량 표시, 모듈 리팩토링을 추가했다.

핵심은 자동화를 늘리면서도 **에이전트 종료·초안 준비·검색 후보·인용·위키 인증을 같은 완료로 취급하지 않는 것**이다. 이 위키는 판단과 작업 맥락을 보존하는 파생 기억이다. 현재 사실은 [현재 상태](../../docs/CURRENT_STATE.md), [사용법과 유지보수 지도](../../.agents/skills/llm-wiki-loop/dashboard/README.md), 코드·테스트·연결된 근거가 우선한다.

초기 UI는 칸반과 그래프 중심이었다. 사용자가 에이전트 작업과 화면의 연결을 물으면서 **자료 맡기기 → 작업 확인 → 반영 확인 → 검증 결과 확인**으로 목적을 명확히 했고, 이후 요청에 따라 채팅을 전면으로 옮겼다. 밝은 테마와 문서 관계 탐색은 유지했다. [초기 결정](../../docs/adr/ADR-0002-local-wiki-dashboard.md), [병렬화 결정](../../docs/adr/ADR-0003-wiki-parallel-preparation.md)이 정본이다.

## 현재 데이터와 실행 흐름

Pi 기본 모델 설정은 명시적으로 바꾸지 않는 한 그대로 사용한다. 원문 합성은 로컬 계정 권한의 에이전트 작업이며 샌드박스가 아니다. 채팅은 별도 제한된 도구 경로다.

```text
브라우저: 대화 / 위키 작업 / 감시 / 문서 / 기록
  ↕ localhost HTTP, Host·Origin·토큰 검사
wiki_dashboard.py: 연결과 프로세스 수명 조립
  ├─ 문서 카탈로그 → 승인된 목록·본문·실제 링크·기존 게이트 상태
  ├─ 읽기 전용 Pi → wiki_list / wiki_search / wiki_read / wiki_links
  │                    → 실제 읽기 후보 → 답변의 명시적 인용
  ├─ 승인된 대화 / 선택형 감시 → raw 기록 → 대기열
  └─ 원문 작업 → 병렬 state 초안 → 한 작성자 → 기존 apply / receipts / seal
                                           ↕
                                   대상 위키 raw / wiki / state
```

### 반드시 유지할 경계

- **소유권:** 정확히 세 스킬을 배포한다. 대시보드는 `llm-wiki-loop` 소유이며 생성된 위키에 실행 파일을 복사하지 않는다. 루트 앱·네 번째 스킬·새 ontology 저장소·별도 완료 원장을 만들지 않는다.
- **채팅:** 범용 셸·쓰기·외부 웹 도구 없이 승인 목록 안에서만 읽는다. 호출·읽은 문서·반환 문량에 한도가 있고, 실제 읽기와 인용은 별도다. 변경된 근거는 무효화하거나 재확인한다. 내부 추론은 표시하지 않는다.
- **쓰기와 완료:** 원문 처리량은 현재 해시와 맞고 수량이 균형 잡힌 단일 applied full receipt에서 읽는다. 기록이 없거나 중복·stale이면 비율을 만들지 않는다. 에이전트 종료나 모든 초안 준비만으로 완료가 되지 않는다.
- **대화 저장:** 최대 40개 메시지·참조 포함 100,000자·메시지당 24개 참조의 10분 미리보기를 승인한다. 표시한 바이트를 내용 해시 raw로 비덮어쓰기 보존한다. 사용자·모델 진술은 검증된 외부 사실로 승격하지 않는다.
- **감시:** 감시와 자동 실행은 별개이며 기본 OFF다. 파일당 2MB·스캔당 500개·두 번의 안정된 관측을 적용한다. 외부 파일은 스냅샷으로 복사하며 원본 수정·삭제나 삭제 전파는 하지 않는다. 기존 파일 포함도 명시적 선택이다.
- **대기열:** 감시를 끄면 감시 항목 자동 실행도 멈춘다. 직접 실행·승인 저장은 별도 권한이다. 실패·중단은 자동 재시도하지 않고, 현재 raw 해시와 기존 게이트로 완료/stale을 재평가한다. 목록은 100개씩 탐색한다.
- **병렬 복구:** 준비 상태는 해시·필수 실제 읽기·초안 해시·원문별 출처에 묶인다. 이전 프로세스 정리 전 재시도는 금지한다. 통합 재개는 준비된 초안을 재사용하지만 게이트를 생략하지 않는다. applied·stale·모호한 고아 run은 자동 복구하지 않는다.
- **폴더 선택:** 파일·숨김·심볼릭 링크를 제외하고 한 디렉터리에서 최대 5,000개 항목을 검사해 200개 폴더까지 반환한다. 본문 수집·재귀 탐색·업로드·모델 호출·자동 연결을 하지 않는다.

상세 한도와 절차는 [사용법](../../.agents/skills/llm-wiki-loop/dashboard/README.md)을 따른다. 이 설명을 별도 정책 구현으로 복사하지 않는다.

## 검색 표시를 오해하지 않는 법

현재 채팅은 Python 문자열 검색(grep 방식)과 위키링크 탐색을 사용한다. 외부 grep 명령을 실행하는 것은 아니며 **FTS와 벡터는 채팅에 미연결**이다. SQLite나 모델 파일이 따로 준비되어도 자동으로 이 경로를 쓰지 않는다.

- SQLite의 최신(stat)은 메타데이터와 경로·크기·수정 시각의 일치다. 본문 전체의 정확한 검증이나 검색 품질 보증은 아니다. 알 수 없는 스키마·변경 중 DB·WAL/저널·검사 한도 초과는 확인 불가로 남긴다.
- ONNX 설정 표시는 현재 서버 Python의 패키지와 환경변수 모델·토크나이저 파일 존재다. 모델 로드·다운로드·추론을 하지 않으며, **설정됨은 추론 성공이 아니다**. 벡터 행 수도 유효성·호환성·준비 완료가 아니다.
- 검색 호출 구성은 **해당 답변의 경로별 정상 완료 호출 수 ÷ 네 경로 정상 완료 호출 수 합**이다. 결과 0건 검색도 1회다. 목록·본문 읽기·실패·한도 거부는 비율에서 제외한다. 답변 기여도·정확도·인용 비율이 아니다.
- 집계는 잘린 이벤트 목록과 별도로 유지한다. 과거 답변은 기록 없음으로 두며 역산하지 않는다. 결과 건수도 고유 문서나 인용 수가 아니다.

근거: [검색 관측 검증](../../docs/evidence/2026-09-06-wiki-retrieval-observability.md).

## 프로젝트 위키와 작업 대상 위키의 구분

DocTology 자체의 `wiki/`는 설계·근거를 보존하는 Repo Docs 기억 공간이고, 생성한 downstream LLM Wiki는 원문 합성 대상이다. 프로젝트에 가짜 raw나 실행 기록을 추가하지 않도록 세 모드를 구분했다.

| 모드 | 허용 범위 |
| --- | --- |
| 예시 | 연결 전 예시 데이터. 실제 실행으로 표시하지 않음 |
| 원문 작업 | loop preflight를 통과한 위키. 원문 합성과 기존 게이트 실행 |
| 프로젝트 읽기 | AGENTS.md·wiki가 있으나 ingest 요건 미충족. 문서 그래프·읽기 채팅만 허용하며 서버도 쓰기를 거부 |

프로젝트 문서 목록은 wiki/meta, docs, 승인된 루트 문서와 스킬 Markdown을 포함한다. 모든 로컬 파일을 공개하는 파일 브라우저가 아니다. 초기 프로젝트 관측은 문서 41개·링크 53개였고 당시 위키는 8개였다. 이 값은 인수인계 추가 전의 역사적 관측이며 현재 개수로 사용하지 않는다. 사용자 코퍼스를 이 저장소로 옮기지 않았다.

| 보류한 선택 | 이유와 다시 판단할 조건 |
| --- | --- |

| Claude 실행기 | 이번 구현에는 없음. Pi보다 빠르거나 좋다는 비교 검증을 한 것도 아님 |

| 검색 엔진 자동 활성화 | 관측 요청과 실행 방식 변경은 다르다. 재색인·모델 설치·FTS/벡터 채팅 연결은 별도 결정 |
| 전역 설치·자동 감시 기본 ON | 소스 배포와 사용자 환경 변경은 분리. 명시적으로 요청받지 않은 설치·감시 설정은 바꾸지 않음 |

## 리뷰에서 배운 것과 재발 방지

| 발견한 문제 | 수정과 남긴 원칙 |
| --- | --- |
| `agent_end`에서 종료하면 후속 작업이 끊김 | `agent_settled`까지 기다림. 설치 버전의 실제 RPC를 확인 |
| 설치된 Pi가 `clear_queue`를 지원하지 않음 | `abort` 사용. 인터넷 예시를 곧바로 실행 계약으로 삼지 않음 |
| 과거 stale 배치가 새 run을 막거나 실패 단계가 정상처럼 보임 | 현재 run_id의 배치만 판정하고 실패 blocker를 표시 |
| 초안 준비와 인증이 섞일 위험 | prepared와 certified를 분리. 기존 apply·질문 영수증·seal만 완료 권한 보유 |
| stat 테스트가 자기 구현을 정답으로 재사용 | 정본 bootstrap indexer와 실제 재색인 fixture를 대조. 메타데이터 일치와 정확 검증도 구분 |

## 다음 작업자가 시작할 위치

1. [현재 상태](../../docs/CURRENT_STATE.md)와 [유지보수 지도](../../.agents/skills/llm-wiki-loop/dashboard/README.md#유지보수와-확장-경계)를 읽는다. 문서 카탈로그·폴더·HTTP는 백엔드 분리 모듈, 기록·검색 표시·Markdown·그래프는 프런트엔드 팩토리가 소유한다.
2. 앱의 변경 가능한 상태·저장소·요청 세대·취소는 `app.js`, 서버 연결·프로세스 수명은 `wiki_dashboard.py`에 남는다. 모듈이 이 전역들을 몰래 참조하지 않게 한다.
3. 새 UI 스크립트는 `index.html`에 defer로 선언하고 마지막 `boot.js` 앞에 둔다. HTTP 제공 목록은 시작 시 읽으므로 서버 재시작이 필요하다. 테스트는 실제 선언 순서와 파일을 변형 없이 사용한다.
4. 실행·동작 변경은 기존 통합 테스트도 유지한다. 단독 모듈 검사가 모델·실화면·게이트 검증을 대신하지 않는다.

```bash
python3 scripts/manage_skills.py check
python3 -m unittest discover -s tests
node --test .agents/skills/llm-wiki-loop/evals/*.test.cjs
python3 .agents/skills/llm-wiki-loop/scripts/wiki_dashboard.py --repo-root . --port 4317
```

마지막 명령은 DocTology 자체의 프로젝트 읽기 모드다. 실제 원문 합성은 별도 호환 wiki-only 대상에서 수행하며 이 저장소에 시험 raw를 만들지 않는다. 검증에는 PyYAML이 있는 기존 QA 환경을 사용했고 전역 패키지 설치는 바꾸지 않았다.

2026-09-06 리팩토링의 로컬 인계 주소는 `http://127.0.0.1:4341/`이었다. URL·PID·루트는 영구 사실이 아니므로 무시된 `state/dashboard-server.json`과 실제 응답을 대조한다. 이전 프로세스는 검사 권한이 없어 건드리지 않았고, 이전 서버는 새 모듈 자산을 제공하지 못하므로 최신 주소를 사용한다.
